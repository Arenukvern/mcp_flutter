# ADR 0021 — Refresh pub.dev OIDC token per package publish

- **Status:** Accepted
- **Date:** 2026-11-10
- **Deciders:** flutter-mcp-toolkit maintainers

## Context

`pub_publish.yml` runs `dart-lang/setup-dart` once at job start. That action
mints a GitHub Actions OIDC token with audience `https://pub.dev` and registers
it via `dart pub token add`. Those JWTs are short-lived (on the order of five
minutes).

`tool/release/publish_pub_packages.sh --execute` publishes multiple workspace
packages in order and calls `wait_for_pub_version` after each upload. A single
tag publish (for example v7.0.2) can therefore exceed the setup-time token
lifetime; the last package (`flutter_mcp_harness`) failed with `Invalid JWT
token: invalid timestamps` while earlier packages had already reached pub.dev.

## Decision

On the `--execute` path only, mint a fresh OIDC token immediately before each
package's real publish (dry-run + `--force` block), using the same GitHub
runner exchange as setup-dart:

- `GET $ACTIONS_ID_TOKEN_REQUEST_URL&audience=https://pub.dev` with
  `Authorization: bearer $ACTIONS_ID_TOKEN_REQUEST_TOKEN`
- export `PUB_TOKEN` from the JSON `value` field (never log the token)
- `dart pub token add https://pub.dev --env-var PUB_TOKEN`

Preflight (`publish_pub_packages.sh` without `--execute`) is unchanged and does
not require OIDC env vars.

## Consequences

- Multi-package publish runs remain within JWT lifetime regardless of
  `PUB_PUBLISH_WAIT_SECONDS` between packages.
- Local fallback publish still uses a manually configured credential; CI
  execute mode fails fast if OIDC env vars are missing.
