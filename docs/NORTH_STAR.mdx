# Flutter MCP Toolkit — North Star

**Status:** active · **Audience:** humans and agents · **Version train:** see [`VERSION`](https://github.com/Arenukvern/mcp_flutter/blob/main/VERSION) (do not hard-code in prose)

## What we are

**Flutter MCP Toolkit** is a **platform-neutral** runtime layer agents use to **see**, **drive**, and **verify** a **debug** Flutter app on any Flutter target. The repo ships the MCP server and CLI (`flutter-mcp-toolkit`, alias `fmtk`, and `flutter-mcp-toolkit-server`), the in-app `mcp_toolkit` package, programmatic `flutter_mcp_harness`, plugin Agent Skills, and the canonical showcase. Host binaries target **darwin-arm64** and **linux-x64**; app wiring works wherever Flutter debug runs (mobile, desktop, web).

## Extension model

1. **App (preferred):** `addMcpTool()` / projections — [custom tools](/use-cases/custom-tools), [ADR 0016](/decisions/0016_toolkit_projections_composition).
2. **Host:** new server `Capability` wired in `mcp_server_dart` — [ADR 0001](/decisions/0001_capability_kernel_and_tool_prefix).

## Distribution

- **Primary:** MCPB bundle `flutter-mcp-toolkit.mcpb` (darwin-arm64 + linux-x64 in one bundle) — [Platforms](/install/platforms).
- **Also:** per-triple tarballs via [`install.sh`](https://github.com/Arenukvern/mcp_flutter/blob/main/install.sh) for CLI/server install.
- **Packages:** one pub.dev version train — `VERSION` at repo root is SSOT; packages stay in lockstep.
- **OCI image:** documented under [Docker](/install/docker).

## Boundaries (non-negotiable)

- **Debug only** — no release-mode instrumentation contract.
- **Observations never lie** — absent JSON key means **unknown**, not empty ([ADR 0024](/decisions/0024_observation_vs_empty_and_change_waits)).
- **First-class entrypoints** in docs and demos — `dart run …`, `fmtk …`, `make …`; no shell glue scripts or Python helpers in examples ([ADR 0025](/decisions/0025_canonical_showcase_and_demo_pipeline)).
- **No hard-coded MCP tool counts** in prose — counts live only in generated [reference](/reference/tools); CI enforces.
- **Strategic why** → ADR; standing **why** → [DESIGN_FAQ](DESIGN_FAQ.mdx); operational **how** → [DX_FAQ](DX_FAQ.mdx).
