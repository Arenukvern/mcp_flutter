# Testing / E2E scenarios

When a flow should run in **CI** or on a schedule, promote it from chat to **checked-in Dart** using **`flutter_mcp_harness`**. Showcase demos live under [`showcase/`](../../showcase/README.md).

## Browser tier (`showcase/web_demo`)

![make drive-web: CdpDriver observe → act → verify](../assets/gifs/harness-web.gif)

```bash
make drive-web
```

Case: static page in headless Chrome — CDP accessibility tree, increment/type/profile, **`OK`** on stdout. Sources: [`showcase/web_demo/`](../../showcase/web_demo/), [`showcase/drivers/bin/drive_web.dart`](../../showcase/drivers/bin/drive_web.dart).

## Instrumented tier (`showcase/flutter_demo`)

![make drive-flutter-chrome: ToolkitDriver on the showcase Flutter app](../assets/gifs/harness-flutter.gif)

```bash
make drive-flutter-chrome
```

Case: `ToolkitDriver` over the VM service — semantic tree, **Count: 3**, screencast frames, named route, ending **`OK — one driver contract, one instrumented Flutter app.`** Sources: [`showcase/flutter_demo/`](../../showcase/flutter_demo/), [`showcase/drivers/bin/drive_flutter.dart`](../../showcase/drivers/bin/drive_flutter.dart). Requires sibling **intentcall** checkout (`tool/ci/checkout_intentcall.sh`).

## Shape

1. Build or launch the app (`MacosAppTarget`, web target, etc.).
2. Attach **`ToolkitDriver`** to the VM service.
3. Observe → act → assert in Dart.
4. `stop()` in `finally` with a non-zero exit on failure.
