# Testing / E2E scenarios

When a flow should run in **CI** or on a schedule, promote it from chat to **checked-in Dart** using **`flutter_mcp_harness`**. Showcase demos live under [`showcase/`](../../showcase/README.md).

## Instrumented tier (canonical + minimal)

![Terminal recording: dart run showcase/drivers/bin/drive_flutter.dart --device chrome](../assets/gifs/harness-flutter.gif)

```bash
dart run showcase/drivers/bin/drive_flutter.dart --device chrome
```

Case: `ToolkitDriver` over the VM service — semantic tree, taps, screenshots, named routes, ending **`OK`**. Default drive target: [`showcase/flutter_demo/`](../../showcase/flutter_demo/) (minimal). The **product** surface is [`showcase/flutter_test_app/`](../../showcase/flutter_test_app/).

Requires sibling **intentcall** checkout (`tool/ci/checkout_intentcall.sh`) when the drive uses IntentCall routing.

## Advanced: browser tier (CDP, not Flutter MCP)

![Terminal recording: dart run showcase/drivers/bin/drive_web.dart](../assets/gifs/harness-web.gif)

```bash
dart run showcase/drivers/bin/drive_web.dart
```

Static page in headless Chrome — CDP accessibility tree, increment/type/profile, **`OK`** on stdout. Sources: [`showcase/web_demo/`](../../showcase/web_demo/), [`showcase/drivers/bin/drive_web.dart`](../../showcase/drivers/bin/drive_web.dart).

## Shape

1. Build or launch the app (`MacosAppTarget`, web target, etc.).
2. Attach **`ToolkitDriver`** to the VM service.
3. Observe → act → assert in Dart.
4. `stop()` in `finally` with a non-zero exit on failure.
