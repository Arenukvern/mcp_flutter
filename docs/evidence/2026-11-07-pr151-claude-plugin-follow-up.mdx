# PR #151 follow-up — design & implementation plan

## Context

[PR #151](https://github.com/Arenukvern/mcp_flutter/pull/151) (merged) fixed `plugin/.claude-plugin/plugin.json`: drop invalid `agents` directory override; add `mcpServers: "./mcp.json"`. `skill_assets.g.dart` still embeds Cursor/Codex manifests at stale `7.0.1` source vs `7.0.0` bundle until `make sync-skills`. Release-please bumps plugin JSON via `extra-files` but not the generated bundle.

## Goals

1. Regenerate `skill_assets.g.dart`; keep drift check strict.
2. Add **targeted** Claude plugin manifest validation (not full official schema; not embedding Claude manifest in the bundle).
3. Harden release PR automation so version bumps and skill asset regen land in a verifiable commit (address GITHUB_TOKEN push not re-firing PR checks).
4. `CHANGELOG.md`: credit [@PiotrMitkowski](https://github.com/PiotrMitkowski) + PR #151 under `## [Unreleased]`; no credit for this follow-up.
5. Fix Docker SDK parity (3.13.0) — evidence from PR #151 / `check_sdk_parity.sh`.

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Dart validator + unit tests in `mcp_server_dart` | JSON parsing and path resolution need tests; matches existing contract test package layout. |
| Enforce known Claude failure modes only | Mirrors `claude plugin validate` errors from PR #151 (`agents` path, `mcpServers` file); avoid claiming full upstream schema compliance. |
| Require `mcpServers` for **this** repo's Claude manifest | Product docs promise MCP registration on marketplace install; omission was the second bug in #151. Omitting `agents` remains valid (default scan). |
| Regen skill assets in **Release PR — sync versions** job | Same `git add -A` commit as `sync_version.sh` keeps manifest bumps and bundle in sync before merge. |
| `workflow_run` on `skill-assets-drift` after sync-skills | Mitigates bot pushes not re-triggering `pull_request` workflows; no new secrets. |
| Do not embed Claude manifest in `build_skill_assets.dart` | Contributor and maintainer docs already exclude it; validation stays separate. |
