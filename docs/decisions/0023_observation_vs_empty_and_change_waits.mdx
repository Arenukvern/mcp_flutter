# ADR 0023 — Observation vs empty, and waiting for unknown UI change

- **Status:** Accepted
- **Date:** 2026-11-24
- **Supersedes (in part):** [0003](/decisions/0003_p0_wait_for_design) — `time` return shape, timeout fields, predicate catalog
- **PR split:** A (items 1–3, 5–7 + schema/docs gates) · B (items 4, 9, 10) · C (items 8)

## Context

An agent drove a macOS chat app, waited for a reply, and keyword-filtered a
semantic snapshot. The reply was already on screen (`label` carried the text)
but the agent treated “no matching keyword in my filter” as “screen empty.”
Separately, `wait_for` polling via `peekSemanticSnapshot()` was rebinding
public `s_N` refs while leaving `snapshot_id` unchanged, so a stale
`snapshotId` check could pass and tap the wrong widget.

Toolkit gaps:

- `time` promised a fresh snapshot in ADR 0003 / skills but returned
  `_successNoSnapshot`.
- Timeout `lastSnapshotId` echoed the non-incrementing peek id — the same
  number the caller already held — so “not observed” read as “unchanged.”
- `semantic_snapshot` had `diff` wired internally but not on schema or handler.
- No `changed` predicate; agents resorted to re-snapshot + substring search.
- `identifierPrefix` does not search labels (correct); agents needed
  `labelPrefix` and guidance.

## General rule (agents and wire shape)

**An absent key never means empty.**

| Key | Absent | Present empty | Present null |
| --- | --- | --- | --- |
| `nodes` | Tree not observed (e.g. `time` with `observe:false`) | N/A | N/A |
| `delta` | Diff not requested or not computed | N/A | `delta: null` + `baseline: "none"` when diff asked but no baseline |
| `observed` | Success path assumed observed tree | N/A | `observed: false` explicit opt-out |

Agents must use `changed`, timeout `delta`, or `semantic_snapshot` with
`diff: true` — not keyword filters on a static snapshot — to discover text they
do not know in advance.

Contract names belong in `Semantics(identifier:)`, not `label`.

## Key design decisions

1. **Peek vs public snapshots:** Only `buildSemanticSnapshot` (`incrementId:
   true`) rebinds `_lastRefMap`. Peeks use ephemeral local maps for predicate
   evaluation only. Every build bumps `observedRevision` (tree walk counter);
   public builds also bump `snapshot_id`.

2. **Timeouts:** `lastSnapshotId` is the caller’s public id at wait start;
   `observedRevision` is the latest peek revision. Capped timeout `delta` (~20
   rows) vs baseline observation at wait start.

3. **`time` + `observe`:** Default `observe: true` — same snapshot envelope as
   `text` success; `observe: false` returns `observed: false` and omits `nodes`.
   **Semver:** minor; default increases snapshot tokens on `time` waits.

4. **`semantic_snapshot` `diff` / `render`:** Schema + handler; `baseline:
   "none"` when no prior observation for filter key.

5. **`changed` predicate:** `{kind:"changed", since:<snapshotId>, settleMs?}`;
   ring buffer of ~8 public observations; evicted `since` →
   `baseline_evicted`; uses `Observation.diff` only.

6. **`labelPrefix`:** Filter + `nearLabels` hint when `identifierPrefix` would
   match nothing but labels share the prefix.

7. **Descriptions:** Single source in `packages/core` (`interaction_tool_descriptions.dart`);
   server + app import it; contract tests lock skill/schema/service parity.

8. **Warnings (PR C):** `warnings:[{ref, reason}]` for tappable-without-name and
   label-as-identifier smell; doctor warns when connected.

9. **`awaitChange` on actions (PR B):** Optional `{settleMs, timeoutMs}` on
   `tap_widget`, `enter_text`, `press_key`, `fill_form` — baseline before act,
   delta in response.

10. **Revision listener spike (PR B):** Prefer semantics-owner notifications to
    bump `observedRevision` without full walks; ship only if reliable — else
    document negative result here (see Implementation notes).

11. **`maxNodes`:** Added to JSON Schema (already supported in filter).

## Tool-surface changes

- `semantic_snapshot`: `diff`, `render`, `lens`, `labelPrefix`, `maxNodes`; output
  `delta`, `baseline`, `nearLabels`, `warnings`.
- `wait_for`: predicates `changed`; `time.observe`; timeout `observedRevision`,
  `delta`, `deltaTruncated`.
- `tap_widget`, `enter_text`, `press_key`, `fill_form`: optional `awaitChange`.

## Follow-ups

- Structured `ObservationDelta` JSON in `universal_automation_semantics` (wire
  uses local maps until upstream adds `toJson()` on delta rows).
- Android emulator proof for `changed` / timeout delta (Linux desktop covered in
  harness tests).

## Implementation notes (revision listener)

Spike uses `SemanticsBinding.instance.ensureSemantics()` handle and samples
`owner.sendSemanticsUpdate` scheduling via frame-boundary counter compare (see
`semantic_revision.dart`). If frame-only revision cannot distinguish intra-frame
mutations, full walk remains on `stable`/`changed` until owner exposes a public
revision — **not shipped as optimization** when spike tests show no gain on
`stable` in CI (recorded in test skip reason).
